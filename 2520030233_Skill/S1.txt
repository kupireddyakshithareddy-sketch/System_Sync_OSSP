Through this skill, I gained practical knowledge of the Linux operating system and its development environment. I learned how to use a Linux virtual machine for programming and system-level activities and understood the process of compiling and running C programs using the GCC compiler. I also learned how to maintain programs in a Git repository by arranging source code, executable files, and other required components in an organized project structure. In addition, I became familiar with the Linux shell and understood how commands entered by the user are processed and executed. I also studied Makefiles and learned how they simplify program compilation by automatically managing the required compilation steps.
A key concept covered in this skill was process management in Linux. I understood that a process is an active instance of a program that is being executed by the operating system. Whenever a program starts, the Linux kernel assigns the process the necessary resources, including memory and CPU time. Each process has important information associated with it, such as a Process ID (PID), Parent Process ID (PPID), current state, and resource details. The process abstraction allows the operating system to manage several programs efficiently and provides each program with a controlled execution environment.
I also learned how new processes are created using the fork() system call. The fork() call creates a child process from an existing process. The original process becomes the parent, while the newly created process becomes its child. Both processes continue their execution separately after the fork operation. The return value of fork() helps a programmer identify whether the code is executing in the parent process or the child process. By working with fork(), I gained a better understanding of process creation and the parent-child relationship maintained by the Linux operating system.
Another important topic was the exec() family of system calls. I understood that fork() and exec() perform two different tasks. While fork() is responsible for creating a new process, exec() loads a different program into an existing process by replacing its current program image. This mechanism is commonly used by shells when executing commands. A shell can create a child process using fork() and then use an exec function in that child to run the requested command. I studied functions such as execl(), execlp(), execv(), and execvp() and learned that they differ mainly in how the program name and command-line arguments are supplied.
I further learned about process synchronization and termination. The relationship between parent and child processes can be examined using their process IDs and process trees. The wait() system call allows a parent process to wait until one of its child processes finishes execution. This provides synchronization between the processes and also enables the parent to obtain information about the child's termination. Understanding fork(), exec(), and wait() together helped me understand the complete sequence of creating, executing, synchronizing, and terminating processes.
The skill also introduced me to the Linux shell architecture and system calls. I understood that the shell acts as an interface between the user and the operating system. When a command is entered, the shell interprets the command and performs the necessary operations to execute it. Many of these operations require communication with the Linux kernel through system calls. System calls provide programs with controlled access to important operating system services, including process creation, file handling, memory management, and program execution.
Finally, I learned how tools such as strace can be used to observe system calls made by a program. System-call tracing helped me understand that even a simple command entered in the terminal may involve multiple interactions between user-level programs and the Linux kernel. This gave me a clearer picture of what happens internally during program execution.
Overall, this skill provided me with a strong understanding of the Linux development environment and process-management concepts. I learned how to compile C programs using GCC, manage projects with Git, automate compilation using Makefiles, understand shell operations, create processes using fork(), execute programs using the exec() family, synchronize processes using wait(), and analyze system-level operations using tools such as strace. These concepts helped me understand how applications interact with the Linux operating system and how the kernel manages running processes.
